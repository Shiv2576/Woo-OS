# Alice evaluation set

135 manual test rows for the intents `search`, `cart_add`, `cart_remove`, `checkout`, `faq`, `order_status`, `clarify`, `other`, plus cross-cutting checks and probes for gaps in the intent list. 70 rows are marked 🔴 **critical**: a failure there breaks the shopper's trust (a wrong cart change, a price, stock, policy, order or delivery fact that is not from your store data, leaked data, or navigating to checkout when it should not).

## How to run

1. Prepare the **test data** below once.
2. For each row, put the store in the row's **Setup** state (table below), type the **User says** text exactly, and compare with **Expected on screen**. Wording does not have to match; the meaning does.
3. Check the **Expected intent** from your agent's log or debug output. Check **Must NOT** every time.
4. A row **passes only if all three hold**: intent correct, screen correct, nothing from Must NOT happened. Record Pass or Fail in the CSV.

**Convention for `clarify`:** the expected intent is `clarify` only when the shopper's _goal_ is unknown ("I need something"). When the goal is known but a detail is missing ("add the Puma one" needs a size), the expected intent is the goal (`cart_add`) and the screen shows the question. If your agent labels it differently, change the convention once and apply it everywhere.

## Test data you need

- A **variable product with sizes** (some sizes sold out) and a **simple product** (socks, a bottle).
- On the S1 screen: one brand **once** (example: Puma) and another **twice** (example: Nike). Two cards sharing a colour for CL-10.
- At least one **sold-out** product and one **on-sale** product.
- A broad category with **30+ products** (for the narrowing questions).
- Policy pages written: **returns** (with a rule for sale items), **shipping**, **payment** (COD yes or no), **warranty**, **contact**. Leave **price matching** undefined on purpose (FQ-09).
- Orders: a customer with 3 orders (processing, shipped with tracking, delivered 20 days ago), a customer with none, and one guest order with a known billing email.
- Examples use a shoes store. Replace names and numbers with your own, keeping the shape.

## Setup states

| Code | Name                           | How to get there                                                                                                                                                                               |
| ---- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S0   | Fresh                          | New session (incognito or cleared cookie). Empty cart, nothing on screen, not logged in.                                                                                                       |
| S1   | Results on screen              | From S0 send `running shoes under 3000`. Six cards visible. One brand appears **once** (example: Puma), another **twice** (example: Nike). At least one card is a variable product with sizes. |
| S2   | Item in cart                   | From S1 add the Puma in size 9. Cart bar shows 1 item. Results still on screen.                                                                                                                |
| S3   | Size question pending          | From S1 send `add the Puma one`. Alice has just asked "Which size?".                                                                                                                           |
| S4   | Which-one question pending     | From S1 send `add the Nike one`. Alice has just asked "Which one do you mean?" with the two Nike names as buttons.                                                                             |
| S5   | Logged-in customer with orders | Logged in as a customer with 3 orders: one **processing**, one **shipped** (with tracking), one **delivered** 20 days ago.                                                                     |
| S6   | Guest with an order            | Not logged in. You know one real order number and its billing email.                                                                                                                           |
| S7   | Brain down                     | Stop the brain service. The store should switch to fallback mode.                                                                                                                              |

## Scoring

- **Overall pass rate** = rows passed ÷ rows run. **Per-intent pass rate** from the same table.
- **Critical rows must be 100%** before you show this to anyone. Fix those first.
- Gap probes are not scored. They tell you which intents are missing.
- Re-run the whole set after every change. A fix that breaks an old row is a regression.

### What you can claim

Passing all 125 scored rows means "passes every scripted check in this set". It does not mean "100% of what shoppers will say". To make the claim defensible: pick about 25 rows at random and **never look at them while building** (your exam), add every real shopper message that fails to this sheet, and quote the numbers instead of a percentage of everything: "N of N scripted checks, M of M critical."
